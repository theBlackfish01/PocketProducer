# Audiotool native render feasibility, 2026-09-23

Environment: Windows, Node 22.14.0, pnpm 11.19.0, `@audiotool/nexus@0.0.17`. This is a bounded experiment, separate from Pocket Producer's `nexus-stem-v3` export workflow. The user confirmed Audiotool Studio was closed before the render calls. No OpenAI or Gemini calls occurred.

## OAuth and scratch project

- The registered client ID, exact loopback callback, and seven scopes were merged into the ignored root `.env` while preserving both existing provider keys. The local API reported `authorized` after browser consent in the user's regular Chrome profile.
- Nexus 0.0.17's browser flow stored the string `"undefined"` when the token response omitted `refresh_token`. The previous 16-character validation rejected the callback. The app now normalizes this marker to a non-refreshable session, encrypts it server-side, and requires reconnection when it expires. Do not treat this as a durable refresh grant.
- The server-side SDK successfully listed projects and created only `projects/ce63417a-32f5-4c24-9bf9-3fb0027deaec`, titled `Pocket Producer native render feasibility 2026-09-23`. [Open scratch project](https://beta.audiotool.com/studio?project=ce63417a-32f5-4c24-9bf9-3fb0027deaec). The local checkpoint prevents duplicate creation or mutation after an ambiguous response.
- A validated SDK transaction inserted one MixerMaster, MixerChannel, Heisenberg instrument, DesktopAudioCable, NoteTrack, NoteRegion, NoteCollection and four notes. A separate Node process read back `[60, 64, 67, 72]`. One later transaction changed the second pitch E4→F4. A fresh process read back `[60, 65, 67, 72]`. This proves native document persistence and editability at the SDK boundary, not that the Studio audio engine played it.

## Render requests and retrieval

The public `AudiotoolClient` exposes no `renderAudio` method, and `SyncedDocument` has none. The [published API guide](https://developer.audiotool.com/js-package-documentation/documents/API.html) lists project, user, sample, preset, role and audiograph services, not a rendering client. The installed package contains generated `DocumentService.RenderAudio` declarations, `RenderedAudio.downloadUrls`, and operation polling declarations, but does not export a supported render client. The experimental probe used the regional service URL returned by the public `projects.openSession` call and made direct JSON RPCs; it is not a production integration contract.

The first request without an explicit auth header returned HTTP 401 `unauthenticated: no (auth) headers provided`. Nexus 0.0.17's `authorizedFetch` helper did not add an auth header for this raw URL, despite its name. That rejected request did not start a render. The corrected request attached the already saved server token without logging it and returned a named operation. After the note change, a second request returned a distinct operation name. Both were sent from Node with Audiotool Studio closed.

For each operation, the regional `OperationService.GetOperation` returned HTTP 501 `unimplemented: render operations are served by public APIs OperationService`. The global public API returned HTTP 403 `permission_denied: insufficient rights` for the same operation. The SDK's generated contract says the completed operation contains download URLs, but neither operation's result could be read. No MP3, OGG or WAV native artifact was retrieved, and completion of either render is unknown. Distinct operation IDs establish acceptance of two render requests, not successful audio generation.

Precise unblock: Audiotool must document/enable an OAuth-accessible `OperationService.GetOperation` path for this registered app and the required permission, or expose an equivalent supported render-result API. The current registered scopes are `user:read project:write project:read sample:write sample:read preset:read preset:write`; do not guess an extra scope or reuse a full-account PAT. Once result retrieval is supported, poll these existing operations if Audiotool permits it before dispatching another render. Then validate playable bytes, compare the two note states, and repeat with Studio closed. The larger production-engine refactor remains gated on that evidence.

The working Pocket Producer preview remains the deterministic 48 kHz stereo WAV renderer. The retained fallback artifact is `.local/repair-20260921-1500-e2e-audio/03f354df-8039-4964-b2d0-309cf679bc74/a8ffd0f6-7a81-4250-a16f-98704d52d7fc/renders/96c84930-9add-4616-873b-13498b08c43c/attempt-1-765b5d13-aa5e-4edf-8d6c-eacf44aa5185/preview.wav` (8,570,228 bytes, SHA-256 `9DBFB282FA254B379DDF3EDD9ADA8F0E23B7DE4CFCA718C738D257C01EEB64D8`). It is not native Audiotool output.

## Reproduce safely

`pnpm spike:nexus-native offline` validates the native structure without network access. `pnpm spike:nexus-native live` reads the checkpointed scratch project without another mutation. `pnpm spike:nexus-render poll-initial` and `poll-revised` only inspect the known operations. The `live`, `revise`, `initial`, and `revised` mutation modes refuse duplicate dispatch based on `.local/evidence/nexus-native-2026-09-23/checkpoint.json`. These live modes require the local Audiotool OAuth session and host network approval. Ordinary test commands remain fixture-only and make zero provider calls.
