# LangSmith producer tracing

The worker uses LangChain/Deep Agents automatic tracing for native construction and the separate legacy arrangement planner. Each graph invocation is named `native-construction` or `legacy-arrangement-plan` and tagged with the workflow and job kind. Metadata contains only the job ID, attempt ID, lease generation, model and native review pass. Use the job ID from Pocket Producer's durable job record to find an attempt in the configured LangSmith project. A resumed native job has a new attempt ID; its confirmed musical steps and provider-effect ledger remain in PostgreSQL, not LangSmith.

The existing ignored root `.env` is loaded server-side. To enable tracing, set `LANGSMITH_API_KEY`, `LANGSMITH_TRACING=true`, and optionally `LANGSMITH_PROJECT`. Set `LANGSMITH_ENDPOINT` for the account's region (without a trailing slash), and `LANGSMITH_WORKSPACE_ID` if the key spans multiple workspaces. Restart the worker after changing these values. Find runs under **Tracing** in the chosen project. The key is never sent to the browser or stored in a trace tag. A configured key alone does not enable tracing.

Pocket Producer defaults `LANGSMITH_HIDE_INPUTS=true` and `LANGSMITH_HIDE_OUTPUTS=true`, even if those names are absent from `.env`. This retains run structure, timing, errors, tags, metadata and model usage where available, while omitting prompts, generated content and tool payloads from trace inputs/outputs. It also limits trajectory inspection. Set either flag to `false` deliberately if that content may be sent to LangSmith for deeper debugging; this can include the user's direction, source metadata, plans and exact note structure. Do not put secrets or user text in trace metadata. Error text and provider-generated metadata may still require review. Set `LANGSMITH_TRACING=false` to stop new traces. `LANGSMITH_TRACING_SAMPLING_RATE` can reduce volume without changing job behavior.

`FIXTURE_MODE=true` forces tracing off. Unit, integration and browser tests also blank the LangSmith key and tracing switch in their processes. Local verification should use scripted/fixture providers and must not create a paid model call or a remote trace. A live trace has **not** been verified by an ordinary test. LangSmith traces are diagnostic telemetry, not the authoritative billing or acceptance record: use PostgreSQL's effect ledger for uncertain calls, reservations and exactly-once recovery, and the native document/version tables for accepted structure.

Implementation follows LangSmith's [LangChain tracing](https://docs.langchain.com/langsmith/trace-with-langchain), [LangGraph tracing](https://docs.langchain.com/langsmith/trace-with-langgraph), [sensitive-data controls](https://docs.langchain.com/langsmith/mask-inputs-outputs), [metadata guidance](https://docs.langchain.com/langsmith/add-metadata-tags) and [sampling guidance](https://docs.langchain.com/langsmith/sample-traces). The persistent worker uses background callbacks and flushes them on graceful shutdown, as recommended for non-serverless JavaScript processes.
