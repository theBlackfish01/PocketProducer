# Text-to-native-music construction pass

This is the current local contract after reviewed baseline `c101db9` and the September 26 expansion pass. A recording is optional. A detailed direction is retained up to 32,768 characters; a vague direction can still start from the same producer. The accepted native v2 document, protected dependencies, immutable revisions, older playable audio and explicit Audiotool sync remain separate. Neither an SDK document nor a plan is a heard recording.

## Run envelope

The chosen **Standard** or **Extended** profile is captured with each new native job in its private request, including model, pricing evidence, reasoning effort, call/input/output limits, deadline and per-job ceiling. A restart uses that captured profile; config changes do not silently increase an old request's allowance. Standard targets 40 model calls, a 64k *conservative UTF-8/framing input bound*, 16,384 maximum output tokens including reasoning for an initial large form, 30 minutes and US$5 per logical job. Extended targets 80 calls, 96k input, 32,768 maximum output, 60 minutes and US$15. After confirmed construction, routine calls use at most 8,192 (Standard) or 12,288 (Extended) output tokens; the reservation uses that actual per-call bound. Environment limits may make all of these smaller. Configurable installation maxima are 300 calls, 256k input-bound units, 65,536 output tokens, six hours and US$100 per job, but defaults remain lower. The separate installation-wide `INITIAL_BUILD_API_BUDGET_USD` still defaults to US$5 and can only be raised explicitly; it is not reset by a new job or profile choice. Unknown provider outcomes retain their reservation; a known truncated response cannot dispatch its partial tool arguments. Only provider-reported cached input tokens receive the captured cached-input price; there is no guessed discount.

These engineering envelopes are **not permission to spend** either proposed amount. Normal tests clear keys or use injected models and do not contact providers. A future live creative comparison needs a separate numeric allowance and no unresolved accounting liability. `pnpm budget:status` reads the ledger without spending.

## Producer and durable truth

The production Deep Agent can record a form/sound/constraint/development plan in `native_job_plan`, advance a stage, read the current workspace, inspect individual parts/motifs/sections and owned-source measurements, search local and connected resources, compose an optional initial form and apply small validated musical batches. The plan and confirmed operation ledger survive worker restart; a changed plan resets its review status. A fresh graph attempt is made after a safe pause while the same job, step/effect identities and accounting continue. The plan is progress; only a checked immutable revision is accepted. A real-model run must review two current sections after its last mutation before recording completion. Scripted models traverse the same tools but do not prove artistic quality. Context compaction retains the original brief and ordered read/error evidence, while compact confirmed state **and the durable plan** are refreshed at each model dispatch. Exact brief windows are retrievable with `read_native_brief`; long text is not copied into every workspace result.

Hard role constraints are conservatively extracted from each role mention and its clause: a preservation request does not become an exclusion, and a localized exclusion such as “no drums in intro” applies only to that section while a later chorus request can still require percussion. Explicit BPM, meter, section spans/lengths, specified role entrances and requested shared parallel drums, sidechain or changing controls are checked against the actual document. An explicitly spelled chord chain such as `Dm9–Bbmaj7–Fmaj9–Cadd9` is checked as ordered bar-level harmony/bass pitch classes, including defining thirds/extensions but allowing omitted fifths. This is a falsifiable symbolic check, not proof of voice-leading quality, correct key throughout or audible harmony. A revision must change the requested role and retain explicitly preserved material; section-scoped preservation compares actual notes, clips, automation and global sound dependencies. Ambiguous durations and subjective goals remain advisory. This bounded parser cannot certify taste, tension, mix perception or every phrasing variation. Real-model review and future listening are separate evidence levels.

## Current validated controls

| Area | Local operation / mapping | Boundary |
| --- | --- | --- |
| Musical form | Tempo, meter, up to 128 bars / 24 sections, parts, exact MIDI notes, motifs, local variations and section edits; one motif placement can receive exact source-note omissions/onset/pitch/duration/velocity edits without changing another placement | Structural timing; no audible judgment |
| Harmony and groove | `harmonizeSection` writes model-chosen exact polyphonic voicings over a repeated cycle; `sequenceSectionPattern` writes pitch, velocity, duration and bounded timing offsets within a section | Best with MIDI-capable instruments; Beatbox8 remains boolean-step only |
| Instruments | Heisenberg A–D waveforms, frequency offset in Hz, detune/modulation links and their supported automation, selected envelopes/LFO, Pulverisateur drive/filter, Gakki with pinned sound discovery, Beatbox8 voice shaping | Only allow-listed SDK ranges mapped into real constructor/automation fields; Beatbox8 steps have no velocity expression |
| Effects | Ordered per-part compressor, EQ, filter, reverb, delay, pitch delay, chorus and tube saturation; per-part dry/wet split; automation of supported serial **and parallel** effect fields | Structural control, not measured heard quality |
| Shared routing | Groups have ordered serial inserts, an independently blended shared dry/wet branch, compressor/sidechain, level/pan/parent routing and automation. Part sends feed shared reverb/delay returns; master gain/pan/limiter remain | Eight groups, bounded chains and SDK-supported routing, not an arbitrary bus graph |
| Local revisions | Crossing notes/motif instances, once-only and exactly-timed looping clips, section-only silence/gain of all clips or one named clip, contained clip moves, crossing-clip section shifts with exact outside phase, stepped/linear automation with retained boundary values | A shifted crossing clip is cropped at section edges; sloped easing splits and noninteger loop cycles are rejected rather than approximated |
| Resources | Owned WAV source regions and resolved Audiotool sample/preset identities with fingerprint checks | Offline mapping evidence; no new live permission/readback result in this pass |

The pinned Nexus `0.0.17` mapper is now `nexus-native-v6`; offline SDK readback checks additional group insert/parallel paths, effect automation and FM parameters. Earlier v2 documents remain readable and can be restored; a previous `v5` remote verification is not silently relabeled as `v6` current fidelity. Bounded deterministic note identities prevent a legal long placement/note ID from breaking section development. All new operations pass native schema and protected hash checks; rejected batches do not replace the accepted version.

## Still open

The full 96-bar/roughly 12-part benchmark and contrasting sparse/vague briefs have **not** been artistically assessed with a real model; structural benchmark-style operations are not a creative-quality verdict. A known, pre-dispatch financial or graph/call/input/output pause can resume on the same logical job after an explicit extension within configured ceilings. The room shows spent, reserved, unknown and site-remaining values separately. A request extension does not increase the installation-wide allowance; uncertain effects, changed heads and cancelled requests refuse continuation. There is no hidden new-job reset. Live expanded Nexus fidelity, remote resource rights and playable native rendering remain unverified or deliberately deferred. No scripted form is a successful original-music claim in audio terms.

Verification commands and exact latest results belong in [STATUS.md](STATUS.md) and [testing.md](testing.md). `pnpm test:integration` uses the separate `_test` PostgreSQL database; browser tests use isolated fixture services and zero provider access.
