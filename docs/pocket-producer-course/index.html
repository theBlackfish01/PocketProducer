01 / The product contract

One composition workspace

At Start, describe a piece, optionally choose an owned WAV, select a producer and a bounded creation profile. Once the request is durably accepted, Producer shows the saved approach beside the growing score. Inspect, revise, compare or explicitly copy a version to Audiotool. There is no second Playable editor or generated-audio history.

Switch the product lens

Compare saved music with the optional recordings used to make it.

A native v2 score, not a recording

Sections, parts, exact notes, reusable motifs, source clips, effects, routing, and automation are saved as an immutable document. You can inspect and revise its structure, compare versions, and explicitly synchronize an editable Audiotool project. Native rendering and playback are intentionally deferred.

No native play button Symbolic inspection

Your recordings, not a preview of the piece

Upload or record an owned sound under Sounds, audition it with labeled seek and volume controls, and select it for your next direction. This plays the original source only. It does not render or play the constructed composition.

Source audition Optional input
The user-facing promise

Construct, inspect, revise

A direction drives a real Deep Agent's validated musical operations. The user can inspect the saved result, preserve parts, and compare immutable alternatives. The score must never imply sound measurements it does not have.

The honesty rule

Editable does not mean audible

A valid SDK document or an Audiotool project link is evidence of structure and mapping. It is not proof the native piece rendered, played, sounded good, or used a source with independent rights.

02 / Infrastructure

A browser request becomes durable work.

The architecture is a TypeScript modular monolith: React/Vite in the browser, Fastify at the boundary, PostgreSQL as durable state and queue, and a worker for expensive construction.

What durable means here

A page reload or worker crash must not make the accepted request disappear—or let a stale attempt commit it twice.

Trace one construction request

The point of each handoff is to preserve identity, ownership, and recoverability.

Submit with a receipt

The browser sends a direction, selected owned-source IDs, profile, revision scope, an idempotency key, and the expected native head. Its project-scoped receipt lets it resolve a lost HTTP acknowledgement without blindly resubmitting.

Accept in one transaction

The API checks identity, ownership, direction length, source selection, and head. It creates the job and outbox row together. The same key plus same request returns the original job; the same key plus different input conflicts.

Claim with a lease

Workers contend through PostgreSQL SKIP LOCKED. Database time, a lease generation, and attempt UUID distinguish the active worker from a dead or stale one. A heartbeat watches cancellation, deadline, and lease health.

Produce recoverable steps

The worker runs the Deep Agent using the producer captured at submission: OpenAI Sol, OpenAI Luna xhigh, or Gemini Flash for new requests. Historical Gateway DeepSeek jobs retain their route. The durable plan, confirmed operations, provider effects, and public activity outlive its process; a crashed worker replays checked steps.

Commit only the current result

Before accepting a revision, the worker rechecks owner, project, expected head, cancellation, lease, deadline, and source hash. A stale attempt may settle observed usage, but cannot select a version.

Observe without making work synchronous

The Producer reads owner-scoped public activity, then receives server-sent events (SSE), with cursor polling on interruption. This activity is a transactional projection of confirmed work, not model reasoning. Confirmed draft/head identities trigger bounded score reads; Refresh arrangement recovers exhausted reads without resending a direction.

03 / Canonical music

The score is the source of truth.

A native v2 document describes the piece in musical time. It is the object that validation, revision, comparison, and Nexus mapping all agree to read.

Time is symbolic

The document uses 960 ticks per quarter note. The Nexus mapper converts that to its SDK time scale; neither number is an audio sample rate.

Illustration only. The product’s actual score is projected from saved notes, motifs, clips, and automation; lane height is note-onset density, not volume.

Open the document in layers

The same saved structure supports different views and constraints.

A bounded musical timeline

Tempo, meter, total bars, and contiguous named sections form the clock. The schema currently allows 4–128 bars and up to 24 sections. Explicit section spans and entrances can be checked against this timeline.

What each instrument actually does

Up to 24 parts carry exact MIDI notes, reusable motif placements, and source clips. A motif variation retains a family and parent link, so changing one placement need not rewrite every occurrence of a theme. Beatbox8 steps are boolean; velocity expression belongs on MIDI-capable parts.

Controls, not heard qualities

Instrument parameters, effects, serial and parallel processing, mixer groups, sends, and supported automation are explicit data. New parts use channel-only gain semantics; old versions retain their saved interpretation. A bare Gakki device is not a kit. Owned WAV regions use a hash and source interval; placement proves neither audibility nor independent licensing.

Immutable versions, movable selection

Each accepted native revision is a new immutable row. A project head points at one row. A successful revision normally selects its new row; “Use Before” or “Use After” explicitly changes local selection. Neither action silently overwrites a synced Audiotool project.

Why strict schemas matter

Operations must fit the score

Unique identities, ordered sections, note boundaries, source hashes, routing, supported parameters, and protected dependencies are validated before a model proposal can replace accepted music. The current offline Nexus mapper is v8.

What they cannot prove

Structure is not taste

A legal chord, automation curve, or motif does not establish memorable melody, convincing phrasing, mix quality, or a heard result. A separate symbolic review can identify some problems, not listen to sound.

04 / Models + Deep Agent

The producer proposes. The application decides.

One Deep Agents/LangGraph workflow runs through the captured OpenAI Sol, OpenAI Luna xhigh, or Gemini Flash route for new work. It plans a form, inspects the score, proposes validated operations and refines. Trusted domain code—not model confidence—decides what can be saved.

A durable creative loop

The selected model, reasoning and price snapshot stay fixed for a job. Its plan and confirmed steps outlive a conversation or worker process; a graph pause does not erase a logical job.

Explore the producer’s toolbox

Tool names reflect real implementation. A read or discovery tool is not write authority.

Plan and retain intent

record_native_plan, read_native_plan, advance_native_stage, and read_native_brief keep musical intention durable. The full direction is retained; long text can be paged instead of repeated in every prompt. A plan is progress, not accepted music. Standard and Extended are engineering ceilings, not authorization to spend their full amounts.

Inspect current facts

Workspace, section, part, motif, and owned-source inspection return bounded, current data. The source profile measures duration and activity—not semantic listening. After its last mutation a real-model run must review two current sections before completion.

Learn what is possible

Capability discovery and local resource search expose supported devices and operations. Original versioned sound recipes guide musical choices without becoming fixed genre generators or heard claims. Connected Audiotool preset, sample, and GM searches are server-mediated; search metadata is not write authority or proof of usage rights.

Apply only validated changes

compose_native_form can begin a new piece. apply_native_batch is the general mutation entry for notes, motifs, clips, instruments, routing, effects, and automation. The model cannot invoke protect through it, run a shell, render audio, ask Gemini to hear native music, or mutate Audiotool directly.

Captured routes

One workflow, three choices

GPT-6 Sol and GPT-6 Luna xhigh use OpenAI Responses; Gemini 3.7 Flash uses Google's compatible route. Historical DeepSeek V4 Pro 0813/Gateway jobs remain readable, but DeepSeek is not selectable for a new request. Selection is not proof of credit or live success. Rewrite/Inspire uses a separate bounded Luna helper.

Scoped workspace

Useful context, narrow authority

The agent has a virtual workspace, repository-local arrangement/revision/sound-design skills, and a PostgreSQL graph checkpointer. Reads are scoped; arbitrary filesystem writes are denied.

Independent completion gate

A valid batch can still be wrong

Code checks explicit bars, tempo, meter, roles, exclusions, sources, chords, processing and required revision change. A focused symbolic critic adds musical judgment, but it does not hear audio; unavailable review is never a clean endorsement.

Where the model is deliberately limited.

“Keep bass” is not “no bass”; “bring in chords” is not a section title. A submit-time interpretation keeps only items that quote the user's words and name real parts; unmatched words are shown and sent as guidance, never as hidden locks. The completion gate cannot prove taste, voice leading, or acoustic mix perception.

Next: the safety net around every proposal and retry.05 / Trust + recovery →
05 / Revision, replay, recovery

A good revision must survive disagreement and interruption.

The user’s selected head, protected material, confirmed operation ledger, and current worker lease all matter. The producer cannot call a revision complete just because it generated plausible-looking notes.

Example request

“Thin the drums in the chorus. Keep the melody and bass.” The checks have to prove a drum change and preservation of the named material.

Walk through a protected revision

This is the actual contract, not a simulation of generated sound.

Inspect, then explicitly choose Change

Opening a section or part is read-only inspection. Choosing “Change this section,” “Change this part,” or the whole piece creates a request scope. “Keep unchanged” adds named protection. The request carries the expected saved head.

Resolve names against saved music

The server previews named preservation and refuses an ambiguous “theme” when several unrelated families fit. Section-scoped constraints apply only where stated. The worker re-evaluates protections against the actual base document.

Serialize validated batches

Even if the model issues simultaneous mutations, the session orders them. Each confirmed step stores its key, operation hash, predecessor document hash, and result hash. The batch must pass schema, scope, protection, source, and SDK checks.

Prove the requested change

The completion gate checks that drums really changed and saved melody/bass material did not. A legal but ineffective edit fails. A bounded symbolic critic may identify musical weaknesses, yet is not listening evidence. Before commit, the worker checks cancellation, lease, deadline, source hash, and original head.

Commit a new immutable version

Success appends a native revision and normally selects it. Comparison then shows Before, After, and Changes. Reading that comparison never switches versions. An explicit Use Before/After changes local selection only.

What happens when the process stops?

Worker crash

Replay, then resume

Another worker can claim an expired lease. It replays saved steps in order and verifies predecessor/result hashes. A settled critic format-recovery result can attach after a restart without a second paid critic call. A stale attempt cannot commit, even if it later reports usage.

Known limit

Partial, not accepted

Confirmed steps may show as Work in progress. A safe call, graph, time, input, output, or budget pause can allow explicit same-job extension and continuation. Continue checks combined, chosen-provider and owner pools as well as job limits; reservation remains the final atomic authority. Leave this draft retains history and costs.

Uncertain effect

Fence, do not repeat

If a provider response may have happened after dispatch, its cost or remote effect remains uncertain. The app preserves the reservation and requires reconciliation; a new key does not make an unsafe retry safe.

Why “immutable history” matters.

A failed, cancelled, or paused attempt cannot replace the accepted score. A selected version and an unfinished draft are visibly separate. Retired test content does not reset the financial ledger or alter saved native versions. The currently paused Lantern job is an example of this boundary, not a finished composition.

06 / Interface

The Listening Room is an evidence surface.

The room makes an arrangement legible without pretending to play it. It separates looking from changing, tentative work from saved versions, and comparison from selection.

Selected visual direction

Warm ivory, forest green, burnt orange, editorial typography, and a spacious desktop-and-phone composition—not a stock dashboard.

Start → Producer

Inspect the score

Start offers a direction, a selected producer, optional Sounds and collapsed Creation options. Rewrite/Inspire supplies an editable suggestion, never an automatic submission. Accepted work opens Arrangement and Producer; confirmed activity is public project state, not private reasoning. Lane density is not loudness.

Sounds

Owned sound stays distinct

The browser can record or upload a WAV and audition it through the shared audio controller. Selecting that source for native construction is explicit. The sampled shortlist can receive measured facts and, when authorized, bounded Gemini character opinion. Auditioning the original WAV is not auditioning the native arrangement.

What does each room state mean?

The interface only makes claims supported by the underlying state.

Looking never silently changes scope

Section focus, part inspector, note pitches, clips, routing, and controls are read-only until a Change action is chosen. The direction form then displays its scope and kept parts, and a server preview resolves preservation before submission.

Confirmed steps, unfinished result

A durable plan and confirmed draft can appear during production or safe pause. It remains visibly unselected. A next direction may be drafted while work runs, but is not sent automatically. Motion can show bounded before/after fact changes, not a fabricated note-by-note performance; reduced motion retains the facts.

Before / After / Changes

The paired views share time, pitch scale, and part order. They detect changed note timing/pitch even with equal note counts, plus known clip/control/routing changes. Unsupported alignment or curve cases say “unverified.” Use Before/After is the separate explicit selection action.

Audition your optional recordings

Sounds contains upload, recording, source selection and one HTMLAudioElement with labeled seek/volume controls. Closing the sheet or leaving the room stops playback and releases recording resources. This is source audition, not composition playback. Versions is separate; Usage and Audiotool connection sit under Session options.

Composition scale

Bounded disclosure

Overview lanes cap visible phrase/clip blocks, focused detail pages bars, and part lanes progressively disclose large arrangements.

Interaction primitives

Owned, themed UI

React/Vite, Tailwind, local shadcn-style Base UI components, Lucide, and Motion for React support accessible dialogs, sheets, menus, controls, and responsive layout.

Device evidence

Tested, with limits

Desktop and emulated phone/tablet Chromium journeys cover scope, focus, comparison, reduced motion, and keyboard space. Physical phones and non-Chromium engines remain open.

07 / Integrations

Crossing into Audiotool is a separate, explicit job.

Nexus is an editability boundary, not a hidden render engine. Gemini is an independent audio-analysis adapter for selected source/sample analysis and future listening, not a listener for native documents.

Fidelity has levels

Native notes and mapped controls can remain editable; an audio clip stays an audio clip; source audio does not become editable MIDI notes.

Follow explicit native synchronization

Current nexus-native-v8 has offline SDK evidence. Midnight Escalator has matching historical live nexus-native-v7 readback; neither is acoustic evidence or proof for every feature.

Choose one immutable version

The user explicitly requests “Copy to Audiotool.” The worker preflights a mapped native document and selected resource identities. Pinned @audiotool/nexus@0.0.17 is used by the current nexus-native-v8 mapper; offline SDK validation checks semantic content, not only object counts.

Record creation before contacting the provider

The sync ledger captures intent and checkpoints the returned project identity. An ambiguous create outcome is fenced rather than repeated into a second project. The adapter refuses to overwrite an occupied target automatically.

Resolve every selected source

Owned WAVs carry source-hash identities, upload/readiness checkpoints, and sample-region mapping. Library samples and presets are re-resolved against recorded identity/fingerprint facts. A local source placement alone is not remote evidence.

Map into an empty project

The adapter converts the score’s 960 PPQ time to the SDK’s 3840 scale and writes supported notes, patterns, instruments, clips, groups, effects, sends, and automation. Unsupported or unsafe approximations fail rather than silently changing meaning.

Reopen for semantic readback

A fresh project read checks the mapped structure against the recorded version and mapper identity. Rechecking a verified project reads without overwriting edits a person made in Studio. Historical v7 verification cannot certify new v8 sound semantics.

Audiotool session

Consent and encrypted tokens

OAuth/PKCE browser consent has worked previously. Tokens are owner-bound and encrypted server-side. The observed grant lacked usable refresh, so an expired connection needs reconnection. Midnight Escalator was reopened twice and structurally matched under its saved v7 identity after read-only reconciliation; no duplicate project was created.

Current live limit

One verified score, bounded evidence

Midnight Escalator's mapped notes, regions, channels and automation matched fresh v7 readback. New v8 sustain and channel-gain mapping, source-bearing synchronization and the full routing/device range need separate live verification. A direct render RPC previously returned operation IDs without a retrievable audio artifact; native playback remains deferred.

Gemini and future listening

Separate adapter

Audio facts versus opinion

The Gemini audio adapter keeps typed character observations separate from measured duration, peak, RMS and activity. The native producer can request bounded, budgeted opinion on shortlisted sample audio; this is distinct from selecting Gemini Flash as the text producer. No whole-composition listening or render–repair loop is shipped.

Honest provider state

Unknown is not success

Retained targeted Gemini audio attempts failed after dispatch with no response metadata. Their billing/outcome remain uncertain and are not automatically retried. Gemini has not heard these native scores.

08 / Operations + evidence

Know what the tests prove—and what they do not.

Pocket Producer protects provider keys, source data, accepted versions, and spend. Its local tests are intentionally provider-free; real-model artistry and current live remote fidelity remain separate questions.

One sentence to remember

Scripted construction proves the workflow can enforce its contract, not that a live model wrote a great song.

Read the evidence label

These categories should never be silently promoted into one another.

Repeatable and provider-free

Unit and PostgreSQL integration tests cover schema, domain invariants, job/restart/contending-worker behavior, replay, cancellation, protected revisions, source ownership, accounting, and offline Nexus mapping. Chromium journeys exercise create/revise/compare/restore, focus, reduced motion, mobile viewport, and larger scores. Scripted model turns traverse the production tool wiring.

Narrow live facts from earlier work

OAuth consent and encrypted session persistence worked. A completed Sol run produced the 40-bar, five-section, five-part Midnight Escalator score with 777 note starts; its copied project matched live v7 structural readback. A later Lantern run has confirmed steps but no accepted version. Neither case proves reliable musical quality.

Do not turn unknowns into badges

Live v8 mapping-range fidelity, source-bearing remote sync, a successful Gemini audio-analysis response, native heard output, broader real-model creative benchmarks, physical-phone keyboard/safe areas, and Firefox/WebKit remain unverified or deliberately deferred. The reconciliation CLI still has a stale v7 label. Public deployment is not part of this milestone.
