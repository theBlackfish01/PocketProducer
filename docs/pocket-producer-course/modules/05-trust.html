05 / Revision, replay, recovery

A good revision must survive disagreement and interruption.

The user’s selected head, protected material, confirmed operation ledger, and current worker lease all matter. The producer cannot call a revision complete just because it generated plausible-looking notes.

Example request

“Thin the drums in the chorus. Keep the melody and bass.” The checks have to prove a drum change and preservation of the named material.

Walk through a protected revision

This is the actual contract, not a simulation of generated sound.

Inspect, then explicitly choose Change

Opening a section or part is read-only inspection. Choosing “Change this section,” “Change this part,” or the whole piece creates a request scope. “Keep unchanged” adds named protection. The request carries the expected saved head.

Resolve names against saved music

The server previews named preservation and refuses an ambiguous “theme” when several unrelated families fit. Section-scoped constraints apply only where stated. The worker re-evaluates protections against the actual base document.

Serialize validated batches

Even if the model issues simultaneous mutations, the session orders them. Each confirmed step stores its key, operation hash, predecessor document hash, and result hash. The batch must pass schema, scope, protection, source, and SDK checks.

Prove the requested change

The completion gate checks that drums really changed and saved melody/bass material did not. A legal but ineffective edit fails. Before commit, the worker also checks cancellation, lease, deadline, source hash, and that the original head is still selected.

Commit a new immutable version

Success appends a native revision and normally selects it. Comparison then shows Before, After, and Changes. Reading that comparison never switches versions. An explicit Use Before/After changes local selection only.

What happens when the process stops?

Worker crash

Replay, then resume

Another worker can claim an expired lease. It replays saved steps in order and verifies each predecessor/result hash. A stale attempt cannot write progress or commit, even if it later reports provider usage.

Known limit

Partial, not accepted

Confirmed steps may show as Work in progress. A safe call, graph, time, input, output, or budget pause can allow explicit same-job extension and continuation within configured ceilings. Leave this draft explicitly ends safe paused work without deleting its history or costs; uncertain effects still block new requests.

Uncertain effect

Fence, do not repeat

If a provider response may have happened after dispatch, its cost or remote effect remains uncertain. The app preserves the reservation and requires reconciliation; a new key does not make an unsafe retry safe.

Why “immutable history” matters.

A failed, cancelled, or paused attempt cannot replace the accepted score. A selected version and an unfinished draft are visibly separate. Retired test content does not reset the financial ledger or alter saved native versions.
