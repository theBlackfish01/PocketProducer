The control desk chooses the request

This asynchronous function decides whether the direction starts a fresh generation or revises the current version.

CODE 
  const submitDirection = async () => {
    if (draft.trim().length < 3) return
    setBusy(true); setError(null)
    try {
      const id = await ensureProject()
      const result = snapshot?.project.currentRevisionId
        ? await api.revise(id, snapshot.project.currentRevisionId, draft)
        : await api.generate(id, draft, snapshot?.assets[0]?.id)
      setJob(await api.job(result.jobId))
    } catch (cause) { setError(cause instanceof Error ? cause.message : "Unable to submit direction") }
PLAIN ENGLISH

Create the action that runs when the listener submits a direction.

Ignore directions too short to be useful.

Show a busy state and clear any old error.

Begin a protected attempt that can report failure cleanly.

Make sure there is a project, and wait for its identifier.

If the current revision exists, request a revision; otherwise request a fresh generation.

Fetch the accepted job so the screen can display progress.

If anything fails, show the clearest available message to the listener.

Meet the specialists

Where would you look first?

Use the symptom and the last successful handoff to choose the smallest useful investigation.

1. A finished preview loads, but pressing play immediately flips back to paused with no new network request. Where should you inspect first?

2. Submit returns an immediate validation error and never produces a job identifier. Which boundary deserves attention?

3. The job is accepted and status polling works, but the production stage stays unchanged while an audio service times out. What is the best first target?
