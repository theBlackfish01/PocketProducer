02 / Infrastructure

A browser request becomes durable work.

The architecture is a TypeScript modular monolith: React/Vite in the browser, Fastify at the boundary, PostgreSQL as durable state and queue, and a worker for expensive construction.

What durable means here

A page reload or worker crash must not make the accepted request disappear—or let a stale attempt commit it twice.

Trace one construction request

The point of each handoff is to preserve identity, ownership, and recoverability.

Submit with a receipt

The browser sends a direction, selected owned-source IDs, profile, revision scope, an idempotency key, and the expected native head. Its project-scoped receipt lets it resolve a lost HTTP acknowledgement without blindly resubmitting.

Accept in one transaction

The API checks identity, ownership, direction length, source selection, and head. It creates the job and outbox row together. The same key plus same request returns the original job; the same key plus different input conflicts.

Claim with a lease

Workers contend through PostgreSQL SKIP LOCKED. Database time, a lease generation, and attempt UUID distinguish the active worker from a dead or stale one. A heartbeat watches cancellation, deadline, and lease health.

Produce recoverable steps

The worker runs the Deep Agent using the producer captured at submission: OpenAI Sol, OpenAI Luna xhigh, or Gemini Flash for new requests. Historical Gateway DeepSeek jobs retain their route. The durable plan, confirmed operations, provider effects, and public activity outlive its process; a crashed worker replays checked steps.

Commit only the current result

Before accepting a revision, the worker rechecks owner, project, expected head, cancellation, lease, deadline, and source hash. A stale attempt may settle observed usage, but cannot select a version.

Observe without making work synchronous

The Producer reads owner-scoped public activity, then receives server-sent events (SSE), with cursor polling on interruption. This activity is a transactional projection of confirmed work, not model reasoning. Confirmed draft/head identities trigger bounded score reads; Refresh arrangement recovers exhausted reads without resending a direction.

No extra queue service is hiding here.

PostgreSQL is both application state and the durable work queue. Private local storage holds uploaded WAVs; inaccessible old test artifacts can remain on disk. Docker supplies local PostgreSQL; there is no public deployment in this milestone.
