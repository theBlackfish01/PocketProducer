Preflight, Not Vibes

How layered tests, durable failure states, and explicit unknowns turn a polished Listening Room into trustworthy software.

Confidence comes from the whole checklist

An aircraft does not pass preflight because its dashboard is pretty. Pocket Producer checks code shape, domain rules, persistence, browser journeys, provider evidence, and the device boundary as distinct layers.

⌁

Types and lint

Catch malformed connections and suspicious code before launch.

🔒

Domain invariants

Prove rules such as ownership, locks, immutable revisions, and safe cost handling.

🗃

Integration tests

Exercise real persistence, claims, retries, and terminal failure states together.

🧭

End-to-end journeys

Drive playback, comparison, focus, and responsive behavior through the browser.

⚡

Live-provider proof

Separate recorded live evidence from fixture responses and adapters that have never called out.

📱

Real-device check

Confirm touch, speakers, browser media rules, and layout on physical hardware—not only a resized desktop.

✦

Aha: every layer answers a different question. A green browser test cannot prove provider credentials, and a successful provider call cannot prove mobile playback.

A restarted worker needs a new boarding pass

This test deliberately expires a lease and checks its fencing generation. The same job is reclaimed, but the newer worker receives stronger authority.

CODE · tests/integration/repository.test.ts 
  it("reclaims an expired lease with a new fencing generation", async () => {
    await dispatchOutbox();
    const firstClaim = await claimNextJob("worker-before-restart");
    expect(firstClaim).not.toBeNull();
    await getPool().query("UPDATE job SET lease_until=now()-interval '1 second' WHERE id=$1", [firstClaim?.id]);
    const secondClaim = await claimNextJob("worker-after-restart");
    expect(secondClaim?.id).toBe(firstClaim?.id);
    expect(secondClaim?.leaseGeneration).toBe((firstClaim?.leaseGeneration ?? 0) + 1);
    if (secondClaim) await failJob(secondClaim, "TEST_COMPLETE", "Expected integration-test terminal state");
    expect((await jobSnapshot(ownerA, secondClaim?.id ?? "")).state).toBe("failed");
PLAIN ENGLISH

Start a test whose promise is: expired work can be reclaimed with newer authority.

Dispatch the queued job, let the first worker claim it, and prove the claim exists.

Move the lease into the past—as if that worker stopped responding.

Let a worker after the restart claim the next available job.

It must be the same job, not a duplicate.

Its generation must be exactly one higher, so the old worker is fenced out.

Finish the scenario with an expected failure and read the durable snapshot.

The database must remember “failed,” even after the worker lifecycle changed.

Compare the browser’s displayed state with the API response and job events before blaming the worker.

Inspect the revision’s asset URL, WAV availability, browser media errors, and the known absence of FFmpeg.

🔌

Provider is unavailable

Check configuration and the recorded effect state; never manufacture a “success” or casually repeat a paid call.

Preflight drill

Diagnose from evidence, not from the most dramatic theory. Pick the next check that narrows the failure without inventing proof.

1. The API returns the newest revision, but the Listening Room still shows the old title. Where should you look next?

2. The Play button becomes Pause, but the speakers stay silent. What is the most useful next check?

3. Gemini has no successful result and the latest transport ended after dispatch without telemetry. What is the honest recovery?
