# Living arrangement and scoped revisions

This is the integrated Listening Room score and polish contract, initially implemented after `bd454ad` and refined after `7563021`. The native v2 document remains canonical; the score does not write notes, infer acoustics, or create audio. The older playable-audio room remains separate.

## Truth and provenance

`apps/web/src/features/native/score.ts` projects saved parts, sections, free notes, transposed/repeated motif placements and owned/library clip intervals into a bounded overview. Density means **note starts per bar**, not amplitude. Up to 120 phrase/clip blocks are drawn per lane in the overview; the caption discloses summarization. A focused section provides a navigable eight-bar SVG detail and part inspector for exact symbolic pitch, timing, velocity, phrase, source interval, device, effect, automation and routing values. Detail is capped and reports truncation. Source interval placement is not proof of audible playback or rights beyond saved metadata.

New motif-instance variations carry `familyId` and `derivedFromMotifId`, so a related phrase can be followed without claiming unrelated phrases are the same theme. Legacy motifs without provenance remain independent. A uniquely active melodic family can be resolved as “the theme”; several families or no identifiable melodic part produce an explicit unresolved prompt instead of a guessed lock. A named role such as bass maps to its actual saved part IDs. The server preview checks ownership, expected selected head and section before reporting the resolution. The actual revision completion gate independently checks named part hashes and theme events against the base version; the preview alone grants no write authority.

The natural-language parser attaches each role mention to its own directive span. “Do not change the bass,” “keep the melody and bass,” and “no drums or bass” have distinct preservation/exclusion outcomes. “Thin drums” additionally requires reduced note-start density, not merely a knob movement. The parser is deliberately bounded; unsupported paraphrases should be made explicit as **Keep** controls or named parts, not presented as guaranteed semantic comprehension. Ambiguous theme identities stop acceptance rather than silently choosing one.

## Version lifecycle and comparison

Inspection is separate from change scope. **Change this section**, **Change this part** or **Change whole piece** sets the scope shown above the direction input. Keep controls and direction then form one scoped request. The existing durable worker runs validated producer operations and checks the candidate before committing an immutable version. An unsuccessful or partial job leaves the accepted head intact; a saved confirmed draft is displayed separately. A successful revision is **automatically selected**, as before, and the room opens Before/After/Changes for the base and new version. Tabs and section navigation are read-only; **Use Before** / **Use After** explicitly changes the selected local head. Reopening an older saved version does not mutate an Audiotool copy.

`compareScoreSection` aligns sections only when ID, bar bounds, tempo and meter agree. It materializes free and motif notes by identity and musical fields, including same-ID pitch edits; compares clip content/phase rather than just clip IDs; evaluates supported step/linear control curves in the chosen section; and includes instrument/shared processing dependencies. Unsupported loop timing, sloped easing, note truncation or changed timing is labeled **unverified**, never “unchanged.” An explicit “Verified unchanged here” list is a structural document claim, not proof of acoustically identical rendered audio. The server's protected-part checks remain stronger authority than a visual diff. Motif-family provenance labels identity, not audible resemblance.

## Motion, responsive behavior and upgrades

The focused section and whole-piece overview are distinct views; the overview can be brought back explicitly while inspecting a section. Shared-processing facts follow the direct and ancestor group chain. Comparison checks those groups' section-local automation and only connected shared send buses. The inspector initially focuses its title (not a deep disclosure); Escape returns to the invoking part, while **Change this part** transfers focus to the direction input.

`native-score.tsx` composes the fit-to-width overview, separate section navigator and progressively disclosed eight-bar detail. The first eight detail lanes render immediately; more are explicitly available. Pitch labels, beat/bar guides and a paired coordinate reference keep Before/After/Changes comparable. The first 120 notes/clips per lane are drawn; the inspector exposes up to 24 exact note/clip facts, controls and routing through a Base UI sheet. It works from the whole-piece view as well as section detail. Step/linear control curves use stored units; unsupported sloped segments are points only. Families have named markers and explicit original/variation relationships; color alone never establishes lineage.

`score-presentation.ts` detects changed stored notes/placements, source/library clips and reachable sound/control dependencies, not just density. `advanceConfirmedFrame` retains the newest observed step per job, ignores duplicate/older receipts and resets on job change/remount. Initial snapshots do not replay history. Added/modified notes use a 360 ms geometry/opacity transition; up to 40 prior note ghosts per animated lane fade over 260 ms; clip changes use 320 ms and curve changes 300 ms. Only the first four visible detail lanes animate (80 note, 40 ghost and 40 clip candidates each); remaining material is static. Overview updates have one grouped 550 ms highlight and a persistent textual explanation. There is no fake sequence, playhead, waveform or audio reaction. Coalesced receipts are described together.

Comparison defaults to relevant parts, with **Include unchanged parts** and explicit **Show the change** replay. Time window, part order and pitch scale remain stable between views. Header/current-version label and version-selection footer stay visible while evidence scrolls. Reading does not write; successful revisions remain automatically selected. Reduced motion presents final geometry immediately with the same facts. The provider/worker/version contracts have not changed.

To upgrade Motion or the Base UI/shadcn component source, pin a compatible version, inspect the generated diff, preserve semantic tokens and labels, then run `pnpm check`, `pnpm test:integration`, `pnpm test:e2e`, `pnpm test:visual` and inspect desktop/390 px/tablet/reduced-motion captures. There is one playback controller only for actual owned/legacy audio; do not connect this score to it until native rendering/playback has its own verified artifact contract.

## Evidence boundary

The production worker scripted-model integration verifies a wrong candidate and subsequent repair, durable version selection and protected bass/lead outcomes. Unit tests exercise real canonical projection, motif lineage, same-ID note edits, loop-split identity, section-local automation and a 128-bar/24-part projection. The isolated Chromium journey creates, scopes, revises, compares without changing the head, selects a saved version, reloads and checks a late cross-room response. Fixture/browser evidence does not certify a real model's creative quality, Audiotool live fidelity, native sound, physical-phone keyboard behavior or Firefox/WebKit rendering.
