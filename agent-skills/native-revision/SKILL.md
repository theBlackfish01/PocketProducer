---
name: native-revision
description: Make localized editable musical changes while respecting part, motif and shared-dependency protection.
---

Inspect the pinned context, durable plan, target part/section and current structural state with `inspect_native_part` or `inspect_native_section`. Discover details only when a device or operation needs them. Use `apply_native_batch` with stable step keys and inspect its actual diff/fresh context. A section development can add a counterphrase or alter a local motif instance; a rhythm request can create a variant instead of changing every occurrence; an instrument request changes the device deliberately; automation should use a short, bounded curve with clear time points. A named part/section is a hard scope, not a suggestion: changes outside it are rejected. If a shared motif occurs outside the section, define a new motif and repoint only the targeted placement. Use `setSectionClipGain` or `silenceSectionClips` with `regionId` when only one crossing clip should change; omitting it affects all clips on that part in the section. `moveSectionClip` retimes one clip that is wholly inside the section and rejects a crossing clip rather than moving material outside the scope. Use `editSectionAutomation` for a crossing stepped/linear curve with exact boundary points; preserve outside sound-source phase and curve values.

Protected parts include their device and pinned preset fingerprint, effects, automation, notes, source regions and dependent motifs, plus tempo/meter and shared routing/return dependencies. A sidechain source that controls a protected group is protected too. Protected motifs cannot be rewritten. If the request conflicts with a lock, leave the accepted version intact and explain the structural conflict. Only the user's explicit protection control can unlock or lock; the model batch tool cannot. Historical preset references without a fingerprint must be deliberately reselected; do not treat the current remote payload as the historical sound. After applying, inspect the new state and summarize exact changes; structural validity is not proof of how the result sounds.
