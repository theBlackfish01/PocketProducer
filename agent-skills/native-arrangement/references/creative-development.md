# Creative development reference v1

This is a supporting skill file loaded into the private runtime. It is guidance,
not permission to ignore the user's brief or to copy an example's pitches.

Before writing: distinguish the listener's explicit constraints from your
interpretations. Record one concise identity, intended density, a few defining
events and exact palette identities in the durable creative state. No uploaded
source does not mean synthesis-only: a connected, permitted library sample is
an option. If library access is unavailable, compose with supported synthesis
and report that choice as yours, not as the user's prohibition.

For a shortlisted library sample, inspect exact metadata and, when its short
WAV is available, measured activity/silence and candidate intervals before
placing it. Optional `analyze_audiotool_sample` can add a bounded Gemini
opinion about character; it costs a provider call, is limited to two distinct
samples per job and is not a rights check or full-mix listening. Keep measured
facts separate from that opinion. An uncertain analysis outcome pauses work;
do not re-dispatch it under a different name or bypass the effect ledger.

For sparse writing, inspect the negative space: phrase length, return timing,
answer register, and a deliberately changed ending. One memorable relationship
can matter more than eight parts. For energetic writing, articulate how pulse,
bass, harmony and hook interlock; stage a middle rise through motif, register,
timbral or rhythmic development and leave a release with contrast. Avoid
equating more notes with more excitement.

Search `search_native_examples` for a relevant idea, then read one example. Its
canonical form is executable but unheard. Examples are references for a
relationship, not patterns to paste. `overbusy-counterexample` is intentionally
valid-but-weak. Compare it with `spare-answer` before adding density.

After each batch inspect actual section and part data. Connect claims about
palette, return, handoff or transition to current section/part/motif/clip IDs
and bar ranges. If a promised event is missing, leave it unfinished in the
durable state. Do not mark unsupported sound/rights or unheard quality as done.
