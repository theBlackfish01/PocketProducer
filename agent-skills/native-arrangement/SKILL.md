name: native-arrangement
description: Construct an editable native musical arrangement from a user's direction using Pocket Producer's validated tools.
---

Text alone is sufficient; owned recordings are optional. Start with `record_native_plan`: capture form, sound goals, explicit constraints and development tasks. The plan is durable progress, not accepted music. Use `advance_native_stage` as construction moves through building, refining and reviewed. A reviewed stage needs inspection of at least two current sections after the last change. On a resumed request, inspect the current document and saved plan before acting; do not repeat confirmed steps.

Prefer `compose_native_scene` for exact integer-tick construction (960 ticks per quarter note); it can add a complete multi-part scene with explicit motifs and placements in one atomic step. Choose all musical content yourself. Aim to construct the first useful identity within roughly ten turns instead of exhausting discovery first. `inspect_editable_sound` answers patch, ranges, writable automation paths and drum-contract questions together; raw SDK fields are not canonical paths. Use `develop_native_theme` to vary named instances or hand motifs between instruments and `shape_native_sections` for local curves/feedback/clip levels. These are shortcuts over the same protected operations, not new write authority.

Prefer `patterns` with `events: [[startTick, durationTicks, pitch, velocity], ...]` over verbose note objects. Note IDs are deterministic; inspect the committed motif before precise note edits. Build the full form with a few core patterns first, then add remaining roles and develop sections in later scene calls (`replaceSeed: false`). Keep individual responses concise; do not attempt hundreds of verbose notes for the entire finished song in one call. This is incremental construction, not permission to finish with a sketch.

All batch/scene/theme/shape tools accept optional `inspect: { sectionIds: [...], soundPartIds: [...] }` (up to three each). Use it to verify a coherent edit without another model round trip. An inspection failure with `committed: true` means the music already changed: retry the read, not the edit with a new key. Replaying an identical step key is idempotent; changed arguments with that key are a conflict. A section-specific request cannot use global sound/routing changes to bypass its scope. Keep existing melody/bass and shared dependencies protected.

The advertised tools stay compact: `compose_native_scene` remains available throughout construction and revision. Later scenes add motifs/placements to existing part IDs without repeating parts or removing the seed. Use `select_native_tools` with `sound` for `configure_native_sound` (patch/mix/effects/automation/shared ambience), `batch` for the complete low-level operation set, `beat-form` for the older beat builder, `library` for connected resources, or `sdk` for raw schema details; `none`/`scene` returns to incremental composition. Scene, sound and batch are alternative menus, not cumulative. Tools remain validated and registered across selection/recovery. Section automation points must include exact section start/end ticks, preserve the end value and any incoming linear boundary value, and use normalized 0–1 values rather than patch Hz/ms/dB. Inspect the existing curve before shaping it.

Finish through a short evidence loop: choose the highest-impact unresolved critic finding, inspect the named material once, apply a coherent targeted batch, verify its actual notes/curves and preserved material, then review the final score. A justified no-change decision is valid; repeated unrelated inspections are not musical development. Use the current finishing checklist and retained findings, not older score snapshots. Aim for useful reviewed work before 50 turns without dropping explicit requirements. An unusable critic result is not approval: format recovery is bounded and still consumes the ordinary call/cost allowance. Do not request repeated reviews of an unchanged valid result. Update task checkboxes and discovery references as bookkeeping; put changed musical requirements in the actual plan/goals, not only in `unfinishedTasks`. Stop optional exploration when the requested music is complete.

Continue later tick scenes for new section material. When low-level edits are needed, select `batch` for `apply_native_batch`: `harmonizeSection` writes chosen chord voicings over a cycle and `sequenceSectionPattern` writes expressive velocity/timing on MIDI instruments. Individual motif and note operations handle other details. The older `compose_native_form` is available only through the optional beat-form menu; it is not required preparation for a scene. Keep stable IDs/step keys, inspect actual differences in at least two sections and refine omissions before ending. Correct a definite rejected write with fresh corrected arguments; never reissue an uncertain effect or a committed edit under a new key.

Read this skill once. Retained local guidance remains valid when its original exchange is compacted. Do not repeat the plan or read the same instructions while the seed remains unchanged. Inspect only the specific control needed, construct with validated settings you know, then refine the confirmed music. A missing optional patch detail is not a reason to delay all composition.

Use sections to give the piece a beginning, development and ending. Prefer distinct roles and instrument colors over copies of one phrase. Define motifs as reusable note relationships, place them in sections, then vary later occurrences deliberately. Inspect a section's onset, overlap and range measurements before declaring its development complete. `developSectionNotes` can alter notes in one section while preserving crossing material elsewhere. `silenceSectionClips` and `setSectionClipGain` split once-only and exactly representable looping clips at section edges while preserving source phase elsewhere; pass `regionId` to edit one clip rather than every clip on that part. A loop whose sample duration cannot map to an integer tick is rejected instead of approximated. `moveSectionClip` retimes one fully contained clip without changing its source offset; `shiftSectionClip` shifts and crops only the chosen section of a crossing clip, retaining original phase and both outside intervals. `editSectionAutomation` splices stepped/linear points with exact boundary values. Sloped easing cannot be split without changing its behavior outside the selection. Beatbox8 is an on/off drum grid: notes use only MIDI 36/38/42/46, sixteenth-step beat positions, quarter-beat duration and velocity 1. Pitched instruments can use expressive velocity and duration. Device/effect parameter names and ranges are in `native-sound-design` and the capability inspector. Route only through supported operations; if a requested device or sample cannot be validated, choose a supported alternative and say so.

For a precise answer or changed ending in only one placement, inspect its original motif and use `varyMotifInstance.noteEdits` with source-note IDs. Omit, move, repitch, resize or reshape the specific notes in a cloned motif; other placements keep their original notes. An unchanged edit is rejected.

Owned sources are optional. A placed interval is only “placed/referenced,” never “audibly used” until its selected bytes and a future render are checked. Do not invent sample IDs, presets or rights metadata. Make assumptions explicit in the structural explanation. No native audio is available in this milestone; do not claim to have listened or judged mix quality.

Read `references/creative-development.md` when deciding density, palette, a defining event or development. Use `search_native_examples` and `read_native_example` selectively; their original canonical forms are unheard references, not templates. Save selected reference IDs and exact chosen resource identities through `record_native_creative_state` before large mutations so they survive context compaction and restart.
